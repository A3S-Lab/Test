# 从一个意图到可重复 Web 测试

A3S Test 把模糊指令收敛成一条可核验的短链路。浏览器提供当前事实，编码 Agent 只选择一个类型化动作，A3S Test 完成动作准入并记录结果，稳定路径最后再进入 ACL 回归。

## 先建立正确的心智模型

```text
可观察意图
  -> 当前浏览器修订
  -> 最小有效动作或差异
  -> 必要时定位负责源码
  -> 明确授权修复
  -> 从变化后页面采集证据
  -> 确定性 ACL 回归
```

这个顺序不能颠倒。截图不能证明组件归属，源码提示不能证明页面已经正确渲染，模型建议也不能授予源码修改权限。每一层只提供一种事实，并保留自己的边界。

## 只选一个入口

| 当前任务               | 使用方式                    | 最终得到什么                                 |
| ---------------------- | --------------------------- | -------------------------------------------- |
| 在本地页面指出一个修改 | Web Test Kit 与本地评审流程 | 绑定页面修订、页面上下文与源码提示的 finding |
| 探索陌生流程或复现问题 | 持久 Agent 会话             | 包含观察、动作和证据的追加式记录             |
| 重复已明确的动作与断言 | ACL 套件                    | 可在本地或 CI 重复运行的确定性回归           |

普通浏览器自动化不强制依赖 Test Kit。需要组件归属、源码候选、渲染几何、视觉证据或人工标记时再接入。

`init`、`doctor` 与 `dev` 本地工程流程已经进入 `main`，会随下一版本发布。已发布的 v1.0.0 二进制尚不包含它们，因此本页先使用已经发布的持久会话命令。

## 安装 CLI 与 Agent Skill

macOS 或 Linux

```bash
curl -fsSL https://github.com/A3S-Lab/Test/releases/latest/download/install.sh |
  sh -s -- --version v1.0.0
```

Windows PowerShell

```powershell
& ([scriptblock]::Create((irm 'https://github.com/A3S-Lab/Test/releases/latest/download/install.ps1'))) -Version v1.0.0
```

安装器会下载当前平台的 CLI、校验 SHA-256，并为检测到的编码 Agent 安装同版本 Skill。只安装 Test Kit、只安装 CLI 或指定 Agent 目录时，请查看[安装指南](./installation.mdx)。

## 1. 声明页面能够证明的结果

先启动本地产品，再写清测试目标和可观察的成功条件。

```bash
a3s-test agent start http://127.0.0.1:3000/checkout \
  --session checkout \
  --goal "Complete checkout with the fixture account" \
  --success "The confirmation heading is visible" \
  --json
```

会话会保留浏览器、精确来源策略和追加式事件记录，直到显式完成、取消或超时。

## 2. 读取真正渲染出来的页面

```bash
a3s-test agent observe --session checkout --interactive --json
```

响应包含新的 `observation_id`，以及只属于本次观察的引用。

```text
observation_id: 1
@e1 [button] Continue
```

| 引用  | 来自哪里              | 权限                                       |
| ----- | --------------------- | ------------------------------------------ |
| `@eN` | 浏览器可访问语义      | 只能在生成它的观察中操作                   |
| `@cN` | Test Kit Page Context | 当前节点仍然唯一且有效时才可操作           |
| `@uN` | UI 理解补充证据       | 永远只读，只关联样式、布局、状态与动效事实 |

页面变化会使 `@eN`、`@uN`、几何和截图失效。只有当前最新观察中的精确 complete delta 明确证明私有节点未变时，`@cN` 背后的稳定定位器才会保留；变化、reset、旧版或不确定绑定都会失效。这样可以阻止 Agent 把旧页面上的决定悄悄套到新页面上。

## 3. 只执行一个通过准入的动作

把动作绑定到刚刚读取的观察。

```bash
a3s-test agent click @e1 \
  --session checkout \
  --observation 1 \
  --json
```

驱动执行前，A3S Test 会校验动作 Schema、会话能力、目标类型、来源策略与观察修订。继续操作时应重新观察，不要复用旧引用。

## 4. 验证变化后的页面并保存证据

成功条件出现后，只保存足以让其他人或 Agent 复查结果的最小证据。

```bash
a3s-test agent screenshot screenshots/confirmation.png \
  --session checkout \
  --json

a3s-test agent finish \
  --session checkout \
  --status passed \
  --summary "Checkout completed and confirmation was observed" \
  --json
```

```text
.a3s-test/agent-sessions/checkout/
├── session.json
├── events.jsonl
├── report.json
└── artifacts/
    └── screenshots/confirmation.png
```

`events.jsonl` 解释每一步准入动作，`report.json` 保存终态，`artifacts/` 只包含本次会话拥有的文件。

## 5. 只固化已经证明的路径

探索用于发现路径，ACL 只保留最小稳定形式。把明确动作、有界等待、断言与证据写入套件，先做静态准入，再真正运行。

```bash
a3s-test check tests/e2e/checkout.acl --json
a3s-test run tests/e2e/checkout.acl --json
```

完整 ACL 示例见[探索与回归工作流](./workflows.mdx)。成功条件涉及控件状态、渲染文本、集合、布局、视口覆盖、指针可达或焦点归属时，请继续查看[断言与稳定性](./assertions.mdx)。

## Test Kit 在哪里接入

Test Kit 在浏览器完成渲染后生成有界上下文。它补充组件归属、稳定定位器候选、多坐标空间几何、排序后的源码候选和人工评审界面，不会替代浏览器可访问树。
