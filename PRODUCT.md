# A3S Test

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

- Coding-agent users exploring unfamiliar Web interfaces and preserving proven paths as deterministic regressions.
- Frontend engineers embedding Test Kit so agents can consume rendered semantics, component identity, locators, geometry, and bounded style context.
- QA and accessibility practitioners who need typed actions, inspectable evidence, and reproducible cross-surface results.
- Maintainers who review a single finding or an ordered batch before authorizing a workspace-owning coding agent to repair it.

## Product Purpose

A3S Test connects exploratory interface testing and deterministic regression testing through one typed execution and evidence boundary. Success means an agent can understand the current surface, admit one safe action, preserve evidence, and turn a verified workflow into stable ACL coverage.

## Positioning

A3S Test combines fresh rendered-page context, revision-bound typed actions, human repair authorization, and inspectable evidence. Browser facts, model advice, human approval, and workspace mutation remain separate authorities.

## Operating Context

- Users start persistent Web sessions from a coding agent or run closed ACL suites in local development and CI.
- Development frontends can embed `@a3s-lab/testkit/react` to publish page context after rendering and expose a human review overlay.
- PRDs, design artifacts, and rendered pages contribute distinct source truth to reviewed Surface Contracts.
- Web, GUI, and TUI adapters share core action, lifecycle, evidence, and result contracts while retaining surface-specific ownership.

## Capabilities and Constraints

- Keep the framework-independent core separate from browser, GUI, TUI, CLI, and model providers.
- Preserve stable JSON fields, error codes, exit codes, cancellation safety, owned cleanup, and explicit authority boundaries.
- The documentation website uses Rspress, defaults to Simplified Chinese, provides English parity, and maintains immutable version snapshots.
- The homepage must retain copyable macOS, Linux, and Windows release installers and pin installer commands on archived documentation versions.
- The homepage experience must import the real Test Kit React package. Its public demo uses in-memory repair storage and must not imply that it mutates a visitor's workspace or contacts a repair agent.
- Product and documentation content must not mention retired implementation inspirations or fabricate customers, benchmarks, adoption, or unsupported platform availability.

## Brand Commitments

- Preserve the A3S Test name and the A3S family relationship.
- The user selected the current A3S Cloud website as the binding visual reference: a light cool-blue canvas, one decisive electric-blue field, compact enterprise controls, generous spacing, and real interface proof in the first viewport.
- Adapt that system to interface understanding, evidence, and human review rather than copying A3S Cloud product claims or diagrams.
- Simplified Chinese is the default documentation language; English is a complete alternate version.

## Product Principles

1. Observe fresh reality before acting.
2. Make every action typed, scoped, and attributable.
3. Preserve evidence that another person or agent can inspect.
4. Keep advice, authorization, and mutation as separate authorities.
5. Demonstrate real product behavior instead of decorating claims.

## Accessibility & Inclusion

The website and embedded experience must remain keyboard navigable, expose correct landmarks and accessible names, preserve visible focus, meet WCAG AA contrast, honor reduced-motion preferences, keep hidden navigation out of the accessibility tree and tab order, and provide complete responsive layouts for Chinese and English content.
